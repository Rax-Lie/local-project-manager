# 通用项目管理插件整体开发指南

> 状态：开发规划基线，待评审。当前仓库只有计划文档和 Git 元数据，不含扩展源码、框架骨架或测试代码。本指南说明后续如何从零搭建并完成首个可发布版本。

## 一、产品范围

插件面向通用本地项目管理场景。项目根路径、目录分区、项目字段、slug 规则、模板和显示语言来自用户配置，不写死任何组织名、客户名、行业字段、盘符或业务目录。

本期项目工作目录必须由插件的新建项目流程创建；历史文件夹不自动导入、不登记为项目。新建项目后，插件将其作为根 `.code-workspace` 的独立工作区项，`folders[].name` 使用中文或用户指定的显示别名。物理项目容器不作为工作区根项，避免容器与其子项目重叠。

首期目标是本地 Windows 工作区。VS Code 扩展 + CLI + SQLite 是候选架构，不视为已经验证的实现。可行性为有条件可行：配置、项目创建和搜索可以分期交付；主要风险是运行时兼容性，以及文件系统、SQLite 和工作区 API 不能组成原子事务。P1 必须验证 CLI 运行时交付方式、最低版本和离线启动，再冻结架构；跨资源写入必须通过操作日志、幂等步骤和启动恢复实现。Node 官方文档目前将 node:sqlite 标为 Release Candidate，发布时应重新核实：[Node.js SQLite 文档](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)。工作区变更通过扩展 API 执行：[VS Code Workspace API](https://code.visualstudio.com/api/references/vscode-api#workspace.updateWorkspaceFolders)。

## 二、仓库现状和目标结构

当前仓库只有 PLAN.md、docs/ 和被忽略的 discuss/ 规划文档，没有源码、框架骨架或测试代码。下列目录是后续按阶段建立的目标：

后续模块按职责拆分，尽量让每个 JavaScript 文件少于 300 行：

```text
src/
├─ extension/       VS Code 命令、TreeView、QuickPick、CLI 客户端
├─ cli/             请求入口、命令分发、进度和取消
├─ application/     初始化、项目创建、查询、归档、恢复等用例编排
├─ domain/          根、模板、项目、操作记录模型和纯业务规则
├─ ports/           Repository、文件系统、操作日志等接口
├─ adapters/
│  ├─ filesystem/   文件系统端口实现
│  └─ sqlite/       数据库端口实现
└─ shared/          协议、校验规则、错误类型和公共常量
tests/
├─ unit/            纯函数和规则测试
├─ integration/     SQLite 与临时目录的组合测试
└─ fixtures/        小型合成工作区
```

目录只有达到文件数量上限时再增加分层；不为了预留未来功能提前创建空模块。adapters 内部按 filesystem 和 sqlite 分组即可，不因预留功能无限拆目录。Workspace API 适配器留在 extension，不进 CLI。

依赖方向为 extension/cli → application → domain；application 依赖 ports，由 adapters 实现。domain 不导入 VS Code API、SQLite 或 Node 文件系统。跨进程只传 JSON DTO，不传 WorkspaceFolder、Uri 或事件对象。建议 CommonJS JavaScript，接口用 JSDoc typedef 和运行时 schema 表达；单文件尽量少于 300 行，每目录尽量不超过 8 个文件，不预建空模块。

### 接口、模型与约定

本节是后续实现和契约测试必须遵循的约定，不是本轮要创建的代码。伪类型仅说明数据形状，不要求改用 TypeScript。

Extension 与 CLI 的标准输入/输出各传一个 UTF-8 JSON 消息。stdout 只输出一条响应，诊断写 stderr。请求头为 protocolVersion:number、requestId:string、operation:string、payload:对应操作 DTO。成功响应为 {protocolVersion, requestId, ok:true, data}；失败响应为 {protocolVersion, requestId, ok:false, error:{code, message, retryable, operationId?}}。每个请求使用唯一 requestId，并校验响应 ID、协议版本、字节上限及退出码。

模板 fieldValues 的动态 JSON 值限定为 null、boolean、number、string、数组或 string 到 JsonValue 的对象；所有动态字段必须按对应模板 schema 校验。核心模型如下：

| 模型 | 必需字段 | 约定 |
|---|---|---|
| RootConfig | schemaVersion:number、rootId:string、displayName:string、workspaceUri:string、configRevision:number、partitions、slugRules | workspaceUri 必须是用户指定的目标工作区；inbox/projects/archive 分区可配置 |
| TemplateField | id:string、label:string、type:text/number/date/boolean/choice、required:boolean、choices?、defaultValue? | choice 必须属于 choices |
| ProjectTemplate | id、revision、displayName、fields、directoryBlueprint、markdownTemplates | 路径骨架必须是安全相对路径 |
| ProjectRecord | projectId、rootId、templateId、templateRevision、slug、displayName、relativePath、status、fieldValues、createdAt、updatedAt | status 为 provisioning/active/archiving/archived/needs_recovery |
| OperationRecord | operationId、kind、state、projectId?、sourceRelativePath?、targetRelativePath?、completedSteps、inversePlanVersion | state 为 planned/applying/awaiting_workspace/completed/needs_recovery/undone |

所有 ID 不可变且不用显示名作主键。相对路径统一使用 / 分隔，由适配器转换成本机路径；时间统一 UTC ISO-8601。模板升级不回写既有项目快照。

存储映射约定：根配置保存在 .pm/pm.json；模板 JSON 文件保存完整定义，SQLite 的 templates 表只存 revision、相对文件路径和启用状态等可重建索引；projects 表保存 ProjectRecord，fieldValues 序列化前按模板 schema 校验；operations 表保存状态机、已完成步骤、逆操作版本和恢复所需路径。P6 才增加可重建的文件索引/暂存索引，不把扫描结果当项目主数据。

CLI 操作名及职责：

| operation | payload 重点 | 结果 | 约定 |
|---|---|---|---|
| system.health | 支持的协议版本 | CLI、运行时、SQLite 能力 | 只读 |
| root.inspect | 根目录 URI | 配置状态、分区、未完成操作 | 只读 |
| root.initialize.plan/execute | 根 URI、workspace URI、配置；execute 带计划摘要和 operation ID | 初始化计划或结果 | plan 只读，execute 可重试 |
| template.list / template.validate | root ID、可选模板 DTO | 模板或字段级诊断 | 不写项目数据 |
| project.create.plan/execute | root ID、template ID、fieldValues；execute 带摘要和 operation ID | slug、相对路径、冲突或待同步项目 | plan 只读，execute 去重 |
| project.workspace.complete | operation ID、workspace 同步观察结果 | 完成或待恢复状态 | 幂等 |
| project.search | root ID、过滤条件、游标、页大小 | 项目 DTO 列表和下一游标 | 只读、稳定排序 |
| project.archive.plan/execute | project ID、目标分区、计划摘要 | 路径变化和待同步状态 | 先预览，execute 去重 |
| operation.recover | root ID、可选 operation ID | 可继续步骤或人工处理原因 | 默认只检查 |

计划摘要绑定规范化输入、根配置 revision、模板 revision 和预期目标；任一变化则拒绝旧计划并重新预览。错误码固定为 INVALID_REQUEST、UNSUPPORTED_PROTOCOL、RUNTIME_UNAVAILABLE、ROOT_NOT_INITIALIZED、VALIDATION_FAILED、PATH_ESCAPE、CONFLICT、PERMISSION_DENIED、DATABASE_BUSY、OPERATION_INCOMPLETE、RECOVERY_REQUIRED、CANCELLED、INTERNAL_ERROR。调用方按 code 分支，不解析 message 文本。

主要 payload 和结果 DTO：

| DTO | 字段定义 |
|---|---|
| RootInitializationInput | rootUri:string、workspaceUri:string、displayName:string、partitions:PartitionConfig[]、slugRules:SlugRules |
| CreateProjectInput | rootId:RootId、templateId:TemplateId、expectedTemplateRevision:number、displayName:string、fieldValues:Record<FieldId, JsonValue> |
| ConfirmedPlan | planId:string、digest:string、operationId:string、expectedConfigRevision:number、expectedTemplateRevision?:number |
| WorkspaceSyncResult | operationId:string、action:add/remove/replace、targetUri:string、displayName:string、observedPresent:boolean |
| ProjectSearch | rootId:RootId、text?:string、status?:ProjectStatus、fieldFilters:FieldFilter[]、cursor?:string、limit:number |
| ProjectPage | items:ProjectSummary[]、nextCursor?:string |
| OperationResult | operationId:string、state:OperationState、changedPaths:RootRelativePath[]、requiresWorkspaceSync:boolean、warnings:Diagnostic[] |

fieldValues 是唯一由模板定义动态字段名的 DTO 成员；FieldId 和每个值仍须由所选模板 schema 校验。分页 limit 必须限制在服务端配置的最小/最大值内；游标绑定排序规则和查询条件，条件改变后拒绝旧游标。

应用服务与端口方法约定：

| 接口 | 方法签名/职责 |
|---|---|
| ProjectApplication | inspectRoot(input) → InspectRootResult；planRootInitialization(input) → RootPlan；executeRootInitialization(plan) → OperationResult；listTemplates(rootId) → ProjectTemplate[]；planProjectCreation(input) → ProjectPlan；executeProjectCreation(plan) → PendingProjectResult；completeWorkspaceSync(result) → OperationResult；searchProjects(query) → ProjectPage；planArchive(input) → ArchivePlan；executeArchive(plan) → PendingWorkspaceResult；inspectRecovery(query) → RecoveryReport；recoverOperation(command) → OperationResult |
| ProjectRepository | getById(id) → ProjectRecord|null；getBySlug(rootId, slug) → ProjectRecord|null；search(query) → ProjectPage；insert(record)；update(record, expectedUpdatedAt) |
| OperationJournal | begin(record)；transition(id, expectedState, nextState)；get(id)；listIncomplete(rootId) |
| SafeFileSystem | inspect(relativePath)；createDirectoryExclusive(path)；writeFileExclusive(path, bytes)；moveNoReplace(source, target)；removeEmptyDirectory(path) |
| WorkspaceAdapter（仅扩展宿主） | contains(uri)；addFolder(uri, displayName)；removeFolder(uri)；replaceFolder(oldUri, newUri, displayName) |

用例返回结构化结果，不直接弹 UI。Repository 将唯一约束冲突转成领域错误；更新校验期望版本/状态；文件写入默认 no-replace，删除只能针对空目录；WorkspaceAdapter 先按规范化 URI 检查再幂等修改。SQL 行和 VS Code 对象不直接暴露给 UI。

WorkspaceAdapter 只能修改当前打开且与根配置 target workspace URI 完全匹配的工作区。目标不是当前工作区、尚未保存或 URI scheme 不支持时返回明确错误，并提示用户先打开正确工作区；不得静默编辑任意 workspace 文件。

### 数据流

**初始化根：** 用户选路径和 workspace → 扩展检查取消、URI scheme 与可写性 → CLI 只读生成 plan、清单和摘要 → 用户确认 → journal 记 applying → 独占创建分区、配置和数据库 → schema/完整性检查 → journal completed。中断后 inspect 返回未完成操作；恢复不能覆盖冲突内容。

**新建项目：** 表单值 → 模板 schema 校验 → slug 和路径计算 → plan 预览 → 用户确认 → journal 先记意图 → 独占创建全新目录和只读快照 → SQLite 写入 provisioning 项目 → 转为 awaiting_workspace → 扩展宿主调用 Workspace API 添加路径/别名 → CLI 收到 complete → 项目 active、journal completed。

Workspace 更新失败时保留 awaiting_workspace 并允许重试，不删除已创建项目。若扩展在 Workspace API 成功后、CLI 确认前崩溃，重启先检查 folder 是否已存在，再补发 complete，确保不会重复添加。

**归档/恢复：** CLI 生成计划和逆操作 → journal applying → 无覆盖移动并更新台账 → 扩展宿主更新/移除活动 workspace folder → CLI 确认 archived。恢复时交叉检查源、目标、数据库和 workspace；撤销前发现用户新增或修改内容就停止，不覆盖或递归清理。

**搜索/暂存建议：** 扩展发送结构化条件 → CLI 校验 → Repository 参数化查询并稳定分页 → 返回 DTO。暂存扫描只产生候选、分数和理由；移动必须另经人工确认。取消或失败的扫描不能据此删除旧索引。

## 四、核心数据和一致性约束

1. `.pm/pm.json` 是根配置权威来源；用户可配置 `inbox`、`projects`、`archive` 的目录名和显示名。
2. 每个模板定义字段名、类型、是否必填、默认值和校验；业务代码只消费通过校验的结构化对象。
3. SQLite 是项目记录唯一真相；模板 JSON 是模板权威来源，数据库模板表仅作为索引。
4. `_project.json` 是数据库生成的只读快照，不反向写入 SQLite。
5. 项目路径在数据库中使用根相对路径；每次写操作前重新规范化、检查根内包含关系及 reparse point。
6. 工作区登记按规范化路径幂等更新，只操作 PM 创建的项目路径，不覆盖用户自定义根项和 settings。
7. SQLite 设置 `foreign_keys=ON`、`busy_timeout` 和 `user_version`；每个迁移先备份，迁移后执行完整性检查。
8. 文件系统与 SQLite 不做“原子事务”假设；所有复合操作在磁盘写入前记录计划、逆操作和状态。

## 五、边界测试条件

### 5.1 协议和进程边界

- stdin 为零字节、纯空白、无效 UTF-8、无效 JSON、JSON `null`、数组、字符串、缺 `version` 或 `operation`。
- 协议版本小于/大于支持范围；未知操作；带未知字段；最大请求字节数刚好等于上限、超过 1 字节、包含多字节中文并越界。
- Node 可执行文件不存在、路径带空格、权限被拒、进程启动失败、超时、用户取消、无 stdout、多个 JSON 行、无效响应、非零退出码。
- stdout 大于响应上限、stderr 大量输出、子进程先 error 后 close；结果只向扩展返回一次。
- Extension Host 触发命令期间仍可响应 UI，不得使用阻塞式 `spawnSync`/`execSync`。

### 5.2 根目录和配置边界

- 用户取消目录选择；不存在、不可写、只读、网络路径、根目录本身是 junction/reparse point。
- `.pm` 不存在、部分存在、配置 JSON 损坏、未知 schema、未来 schema、配置中目录名重复或包含绝对路径/`..`。
- 首次初始化、连续初始化两次、已有同名目录/文件、已有 workspace 文件且包含自定义 settings。
- 配置目录名称含空格、中文、大小写差异、尾随点/空格和 Windows 保留设备名。
- 初始化 dry-run 对真实路径只读；取消确认后目录项数量、配置和时间戳不变。

### 5.3 项目字段、slug 和工作区边界

- 必填字段为空、可选字段为空、字段类型错误、额外字段、极长字段、控制字符、非法路径字符和仅含分隔符。
- 两个不同项目产生同一 slug；目录已存在但数据库无记录；数据库已记录但目录缺失；仅 workspace 已含同路径。
- 用户输入修改 slug；大小写不同的 slug 冲突；路径长度临界值及超限；多字节 alias 不得影响磁盘 slug。
- 当前打开的不是目标根工作区、无保存的 workspace、workspace 只读、folder URI 非本地 file、API 更新失败。
- 新增 workspace item 后重启 VS Code；幂等重建；保留用户自定义 folders/name/settings；工作区中不登记历史目录。
- 活动项目改名不改路径；路径转换更新同一 workspace 项；归档移除活动项后仍可从归档目录访问。

### 5.4 SQLite 和迁移边界

- 数据库不存在、零字节、损坏、权限不足、磁盘空间不足、锁冲突、WAL/SHM 文件存在。
- 外键引用不存在模板、重复 slug/path/id、超长字符串、NULL 必填字段、未知状态枚举。
- 从每个受支持 schema 版本逐级升级；中断迁移；备份损坏；恢复后 `quick_check` 失败。
- 同时触发两个命令写入；一个写入持锁；等待超时后清楚报错且数据库状态未部分提交。

### 5.5 文件系统、撤销和崩溃恢复边界

- 目标已存在空目录/非空目录/同名文件；源文件被删除、重命名、只读或被 Office 占用。
- 路径穿越、盘符变化、UNC、junction 链接逃逸、大小写冲突、超长绝对路径、同卷与跨卷移动。
- 在“写日志后、mkdir 后、文件移动后、SQLite 提交后、workspace 更新后、标记完成前”逐点强制终止进程并重启。
- 撤销时源/目标均存在、均不存在、内容后来被修改、用户新增文件；必须停止并报告，不覆盖、不递归删除用户数据。
- 不完整扫描取消后不得据此删除索引；全量扫描成功后才能淘汰未见记录。

### 5.6 暂存建议与 Markdown 附件边界

- 无候选项目、多个同分候选、置信度临界、中文同音/简称冲突、空文件名、超大文件元数据。
- 归类建议只做推荐；拒绝、改选、忽略状态可重复处理且不移动文件。
- Markdown 链接测试覆盖 fenced/inline code 排除、引用式链接、括号嵌套、转义、HTML `href/src`、URL 编码、query/fragment、相对路径越界、UNC/盘符绝对链接和缺失目标。
- 如果选用第三方 Markdown 解析器，覆盖其版本锁定、离线安装和许可证；若不采用，缩小支持语法并把不支持项列为验收限制。

## 六、验收与发布门槛
